# 03-阶段流程与质量门禁

> 本文档把 InspireSpec 拆成 A-G 七个阶段。每个阶段都有输入、动作、产物和出口条件。

---

## 1. 阶段总览

| 阶段 | 名称 | 输入 | 产物 | 出口条件 |
|------|------|------|------|----------|
| A | 设计接收、PRD 与差距分析 | 功能设计、界面设计、交互说明 | 设计资产清单、PRD、差距报告 | 需求范围和验收标准已确认 |
| B | 数据建模与通用约束 | PRD、设计稿、已有代码/数据库 | 数据字典、ER 图、通用约束 | 字段语义唯一，P0/P1 规则有测试点 |
| C | 接口契约、状态机与核心时序 | 数据字典、通用约束、模块草图 | 接口/API/设备契约、状态图、时序图 | 核心流程和异常路径无歧义 |
| D | 4+1 视图与实现规划 | PRD、契约、时序图 | 4+1 视图、RTM、任务清单 | 需求可追踪，依赖无环 |
| E | 编码实现与单元测试 | 任务清单、规格文档 | 代码、单元测试、变更日志 | 核心逻辑有测试，变更影响面已记录 |
| F | 集成测试与回归验证 | 代码、测试计划、RTM | 测试报告、缺陷清单 | 无 P0/P1 缺陷，设计实现一致 |
| G | 发布准备与复盘 | 测试结论、部署清单 | 发布清单、复盘报告 | 部署验证通过，经验已沉淀 |

---

## 2. 阶段 A：设计接收、PRD 与差距分析

### 目标

确认上游设计资产能否进入工程实现，并把分散的功能说明整理成 PRD。

### 必做动作

1. 清点功能蓝图、页面流转图、界面稿、设计令牌、组件库、技术映射。
2. 提取用户角色、业务场景、范围内/范围外。
3. 为每个核心功能写验收标准。
4. 识别工程差距：数据、约束、接口、状态、架构、测试、部署。

### 产物

- PRD 产品需求文档
- 设计资产清单
- 差距报告

### 门禁

- [ ] 每个核心功能都有验收标准。
- [ ] 范围外已明确。
- [ ] 差距项有严重度和处置阶段。

---

## 3. 阶段 B：数据建模与通用约束

### 目标

统一实体、字段、枚举、关系和跨模块业务规则。

### 必做动作

1. 提取所有核心实体。
2. 为字段定义类型、约束、默认值、语义。
3. 把状态字段转成枚举或受控常量。
4. 绘制 Mermaid `erDiagram`。
5. 提取通用约束和业务规则。

### 产物

- 数据字典
- ER 图
- 通用约束与业务规则

### 门禁

- [ ] 每个共享字段语义唯一。
- [ ] 每个状态字段有进入条件和可转换目标。
- [ ] P0/P1 规则有编号和测试点。

---

## 4. 阶段 C：接口契约、状态机与核心时序

### 目标

定义模块、前后端、设备之间如何交互，并明确关键流程顺序。

### 必做动作

1. 为核心模块/API/设备接口写输入、输出、副作用、异常。
2. 绘制 Mermaid `sequenceDiagram`，覆盖正常路径和异常路径。
3. 为复杂状态对象绘制 `stateDiagram-v2`。
4. 检查接口两端是否匹配。

### 产物

- 接口/API/设备契约
- 核心流程时序图
- 状态机图

### 门禁

- [ ] 每个跨模块调用有契约。
- [ ] 每个核心流程有时序图。
- [ ] 异常路径有处理策略。

---

## 5. 阶段 D：4+1 视图与实现规划

### 目标

从架构角度确认系统边界，并拆解实现任务。

### 必做动作

1. 生成用例视图、逻辑视图、开发视图、进程视图、物理视图。
2. 建立需求追踪矩阵。
3. 拆解任务，标注依赖与实现顺序。
4. 检查孤儿需求和幽灵实现。

### 产物

- 架构 4+1 视图
- 需求追踪矩阵
- 任务清单

### 门禁

- [ ] 每个需求有实现和测试落点。
- [ ] 每个核心场景能被架构视图解释。
- [ ] 任务依赖无环。

---

## 6. 阶段 E-G：实现、验证、交付

### 阶段 E：编码实现与单元测试

- 先读规格，再写测试，再写代码。
- 修改规则、字段、接口时必须同步文档。
- 每次关键改动写变更日志。

### 阶段 F：集成测试与回归验证

- 按 RTM 逐项验证需求。
- 按通用约束验证 P0/P1 规则。
- 按时序图验证主链路和异常链路。

### 阶段 G：发布准备与复盘

- 检查部署依赖。
- 输出发布清单。
- 记录复盘和方法论改进项。

---

## 7. 阶段回退规则

| 发现问题 | 回退到 | 原因 |
|----------|--------|------|
| 需求边界不清 | A | PRD 未定，后续全会漂移 |
| 字段语义冲突 | B | 数据事实源不可靠 |
| 通用规则冲突 | B | 跨模块规则必须先统一 |
| 接口两端不匹配 | C | 无法联调 |
| 架构边界不清 | D | 实现任务无法稳定拆分 |
| 测试无法设计 | A-C | 说明需求、数据、约束或流程不够明确 |
