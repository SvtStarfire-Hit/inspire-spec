# 02-工程规格层

> 工程规格层位于“初期功能设计 + 界面设计”和“软件/硬件开发”之间。它把设计语言翻译成开发、测试、部署都能执行的工程事实源。

---

## 1. 总体链路

```mermaid
flowchart LR
    Idea[初期想法] --> Feature[功能设计]
    Feature --> UI[界面与交互设计]
    UI --> PRD[PRD]
    PRD --> Data[数据关系设计]
    Data --> Rules[通用约束]
    Rules --> Arch[4+1架构视图]
    Arch --> Contract[接口/API/设备契约]
    Contract --> Diagram[Mermaid图表]
    Diagram --> RTM[需求追踪矩阵]
    RTM --> Dev[软硬件开发]
    Dev --> Test[测试验收]
    Test --> Release[部署复盘]
```

---

## 2. 核心产物

| 顺序 | 产物 | 做到什么程度 | 起什么作用 |
|------|------|--------------|------------|
| 1 | PRD 产品需求文档 | 范围、角色、功能、非功能需求、验收标准明确 | 建立产品事实源 |
| 2 | 数据字典与 ER 图 | 实体、字段、枚举、关系、字段语义明确 | 建立数据事实源 |
| 3 | 通用约束与业务规则 | 跨模块规则有编号、等级、影响范围、测试点 | 统一业务规则 |
| 4 | 4+1 架构视图 | 用例、逻辑、开发、进程、物理五个视图完整 | 建立系统边界 |
| 5 | 接口/API/设备契约 | 输入、输出、副作用、错误、权限、幂等清楚 | 支撑并行开发和联调 |
| 6 | Mermaid 图表 | 流程、时序、状态、类图、ER 图可维护 | 降低理解偏差 |
| 7 | 需求追踪矩阵 | 需求→设计→代码→测试全链路可追踪 | 防止遗漏与幽灵实现 |
| 8 | 测试计划 | 正常、边界、异常、回归场景明确 | 证明实现正确 |
| 9 | 部署/硬件清单 | 软件、硬件、网络、驱动、模型、配置明确 | 降低现场风险 |
| 10 | 变更日志与复盘 | 改动原因、影响面、经验教训可追踪 | 建立持续改进闭环 |

## 3. 实现顺序

### 3.1 先定 PRD

PRD 是“做什么”的事实源。它必须包含：

- 背景与目标
- 用户角色与使用场景
- 范围内与范围外
- 功能需求与验收标准
- 非功能需求
- 关键业务规则索引

### 3.2 再定数据关系

数据字典是“系统认识世界的方式”。它必须包含：

- 实体定义
- 字段类型、约束、默认值、语义
- 枚举与状态字段
- Mermaid `erDiagram`
- 与现有代码/数据库的偏差清单

### 3.3 再定通用约束

通用约束是“所有模块共同遵守的规则”。它必须包含：

- 规则编号
- 严重等级 P0/P1/P2
- 适用模块
- 禁止事项
- 异常策略
- 测试点

### 3.4 再定架构与契约

4+1 视图回答“系统怎么组织”，接口契约回答“模块怎么协作”。

- 用例视图：谁使用系统
- 逻辑视图：系统有哪些模块
- 开发视图：代码如何组织
- 进程视图：运行时如何协作
- 物理视图：部署在哪里、依赖什么

接口契约要覆盖模块接口、HTTP API、设备通信、事件通知、文件格式。

### 3.5 再画 Mermaid 图表

图表不是装饰，而是规格。推荐使用：

| Mermaid 类型 | 用途 |
|--------------|------|
| `erDiagram` | 实体关系 |
| `sequenceDiagram` | 模块/服务/设备调用顺序 |
| `flowchart` | 业务流程、页面流转、部署拓扑 |
| `stateDiagram-v2` | 状态转换 |
| `classDiagram` | 类、接口、模块关系 |

### 3.6 最后追踪、测试、交付

- RTM 确认每条需求都有实现和测试。
- 测试计划覆盖核心规则、边界条件、异常路径。
- 部署清单确认环境、硬件、网络、模型、配置。
- 变更日志记录每次修改的原因和影响面。

## 6. 软硬件开发前必须额外明确

| 类别 | 必须明确 |
|------|----------|
| 硬件 | 型号、固件、驱动、接口、供电、网络 |
| 通信 | 协议、端口、认证、心跳、超时、重试、幂等 |
| 数据 | 单位、量纲、范围、采样周期、时间戳 |
| 部署 | 终端、边缘、中心、网络、防火墙、存储 |
| 异常 | 断网、断电、设备离线、缓存堆积、时间不同步 |
| 验收 | 模拟设备、真实设备、压力、恢复、现场清单 |
