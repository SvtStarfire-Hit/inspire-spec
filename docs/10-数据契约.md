# 10-数据契约

> 所有内容（文档端 + 未来 MCP/Web 端）共享的同一份数据结构的定义。
>
> 本文件是 InspireSpec 的**接口层**：它定义了阶段约束包的字段结构，使未来的 MCP 服务和页面端能消费同一份数据。当前阶段内容硬编码在 Markdown 文档中；当需要工具化时，按本契约外置为 JS/JSON 数据模块。

---

## 1. 总原则

1. **单一事实来源**：流程内容只维护一份，文档端与未来的 MCP/Web 端消费同一份数据
2. **原型阶段固化**：内容硬编码在 Markdown 文档中（当前形态），未来外置为 JS 数据模块
3. **结构先行**：本文件定义的字段结构是稳定的；内容（各阶段的文本）可随时改
4. **场景扩展机制**：不同项目类型（Web/软硬件）可通过场景扩展字段覆盖通用阶段内容

---

## 2. 阶段约束包（StageContract）

MCP 核心工具的返回物。每个阶段的完整约束信息。

### 2.1 字段定义

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 阶段标识：`intake` / `data` / `contract` / `arch` / `implement` / `verify` / `release` |
| `number` | number | 阶段序号（A=0, B=1, …, G=6） |
| `name` | string | 阶段名（如"数据建模与通用约束"） |
| `goal` | string | 一句话目标 |
| `deliverables` | object[] | 产物清单：`{ name, description, path? }` |
| `exitCriteria` | string[] | 出口条件（怎么算做完） |
| `dependencies` | object[] | 前置依赖：`{ stageId, deliverable, hint }` |
| `rules` | string[] | 本阶段的硬规则 |
| `guidance` | string[] | AI 引导用户的步骤要点 |
| `aiPromptTemplate` | string | 可复制的提示词模板 |
| `pitfalls` | string[] | 常见坑 |
| `revisionImpact` | string[] | 回退影响面：改本阶段产物后需复查什么 |
| `humanCheckpoint` | string | 人确认点的描述 |
| `checklist` | string[] | 门禁清单（可勾选的检查项） |


## 3. 场景扩展（SceneExtension）

不同项目类型（Web 前后端、软硬件协同等）对通用阶段内容的差异覆盖。

### 3.1 字段定义

```jsonc
{
  "id": "web",                          // 唯一标识
  "name": "Web 前后端场景",
  "description": "面向 Web 前后端分离架构",
  "status": "available",                // available（已有）/ planned（规划中）
  "stageOverrides": {                   // 字段级覆盖（只写要改的字段）
    "contract": {                       // 阶段 C 的覆盖
      "deliverables": [                 // 数组字段为整体替换
        { "name": "API 契约", "description": "RESTful/GraphQL 接口定义" },
        { "name": "数据库 Schema", "description": "表结构、索引、迁移脚本" },
        { "name": "核心流程时序图", "description": "前后端调用时序" }
      ],
      "rules": [
        "API 契约必须包含 HTTP 方法/路径/请求体/响应体/错误码",
        "数据库变更必须有迁移脚本"
      ]
    }
  }
}
```

### 3.2 覆盖语义

- **字段级覆盖**：只写要改的字段，其余继承通用版
- **数组合并**：数组字段（`deliverables` / `rules` / `guidance` / `exitCriteria` / `pitfalls` / `checklist` 等）为**整体替换**，不是逐项合并。场景扩展中定义的数组将完全取代通用版同名字段，因此必须包含该字段的完整内容

### 3.3 已有场景

| 场景 | 状态 | 主要差异 |
|------|------|----------|
| Web 前后端 | 已有（见 [07-Web前后端场景扩展.md](./07-Web前后端场景扩展.md)） | API 契约、数据库 Schema、认证授权、错误码 |
| 软硬件协同 | 已有（见 [08-软硬件协同场景扩展.md](./08-软硬件协同场景扩展.md)） | 硬件清单、通信契约、部署拓扑、异常恢复、现场验收 |

## 4. 未来 MCP 工具设计（规划中）

当 InspireSpec 实现 MCP 服务时，核心工具接口如下：

### 4.1 工具清单

| 工具 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `get_stage_checklist` | `stage: string` | StageContract | 返回指定阶段的完整约束包 |
| `list_scenes` | 无 | SceneExtension[] | 列出所有可用的场景扩展 |
| `get_scene_guidance` | `scene: string, stage: string` | StageContract（合并后） | 返回场景覆盖后的阶段约束包 |

### 4.2 设计原则（与 InspireDesign 对齐）

| 原则 | 说明 |
|------|------|
| 粗粒度 | 一个 `get_stage_checklist` 返回完整约束包，不拆成细碎工具 |
| 无状态 | 工具不记住进展；约束包里带 `dependencies`，AI 据此判断当前该做什么 |
| 任意跳转 | 允许 AI 在任何时候取任意阶段的约束（支持回退修正） |
| 场景覆盖 | 通过 `get_scene_guidance` 返回合并后的约束，而非让 AI 自己做合并 |

## 5. 演进路线

| 阶段 | 存储方式 | 触发条件 |
|------|----------|----------|
| 现在（原型） | 内容硬编码在 Markdown 文档中 | — |
| 第一步 | 外置为 `data/stages.js`（Node 可 import 的 JS 数据模块） | 需要 MCP 服务时 |
| 第二步 | 实现 MCP 服务（`get_stage_checklist` 等工具） | 需要在 AI IDE 中直接消费时 |
| 第三步 | 实现 Web 页面端（浏览方法论 + 复制提示词） | 需要独立浏览时 |

**契约（本文件）在以上演进中保持不变**——它是接口，存储是实现。

## 6. 与 InspireDesign 数据契约的对齐

| 维度 | InspireDesign | InspireSpec | 对齐方式 |
|------|--------------|-------------|----------|
| 阶段约束包 | StageContract（16 字段） | StageContract（14 字段） | 字段结构对齐，Spec 去掉 `modeId`（改为场景扩展）和 `capabilities`（Spec 暂无工具链） |
| 模式/场景覆盖 | Mode.stageOverrides（字段级覆盖） | SceneExtension.stageOverrides | 覆盖语义相同（字段级浅合并，数组整体替换） |
| 核心工具 | `get_stage_guidance(mode, stage)` | `get_stage_checklist(stage)` + `get_scene_guidance(scene, stage)` | Spec 拆为两个工具，因为场景覆盖是可选的 |
| 设计原则 | 粗粒度、无状态、任意跳转 | 粗粒度、无状态、任意跳转 | 完全对齐 |
