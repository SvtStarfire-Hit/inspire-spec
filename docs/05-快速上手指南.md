# 05-快速上手指南

> 本指南给出最短实操路径：从已有功能设计和界面设计，生成一套能指导开发的工程规格。

---

## 1. 开始前准备

你需要准备：

- 功能设计或项目设计文档。
- 页面流转图或业务流程说明。
- UI 设计稿、组件状态、交互说明。
- 技术栈或目标运行环境。
- 如果已有代码，也提供代码目录。
- 如果涉及硬件，提供设备型号、协议、部署环境。

---

## 2. 第一步：生成 PRD

使用模板：`../templates/PRD产品需求模板.md`

操作：

1. 从功能设计和界面稿提取用户角色。
2. 列出范围内和范围外。
3. 把每个功能写成可验收需求。
4. 补充性能、安全、兼容、稳定性要求。
5. 标出需要人工裁定的问题。

产出：`PRD产品需求文档.md`

---

## 3. 第二步：生成数据字典和通用约束

使用模板：

- `../templates/数据字典模板.md`
- `../templates/通用约束与业务规则模板.md`

操作：

1. 提取所有实体、字段、枚举和状态。
2. 绘制 Mermaid `erDiagram`。
3. 找出字段语义容易误解的地方。
4. 把跨模块规则集中成通用约束。
5. 为 P0/P1 规则写测试点。

产出：

- `数据字典与实体关系.md`
- `通用约束与业务规则.md`

---

## 4. 第三步：生成接口契约和核心时序图

使用模板：

- `../templates/接口契约模板.md`
- `../templates/核心流程时序图模板.md`

操作：

1. 列出核心模块、API、设备或外部系统。
2. 为每个接口写输入、输出、副作用、异常。
3. 为主链路画 Mermaid `sequenceDiagram`。
4. 为复杂状态画 `stateDiagram-v2`。
5. 检查接口两端是否匹配。

产出：

- `接口契约.md`
- `核心流程时序图.md`

---

## 5. 第四步：生成 4+1 架构视图

使用模板：`../templates/架构4+1视图模板.md`

操作：

1. 用例视图：用户、外部系统、设备和业务场景。
2. 逻辑视图：模块、领域对象、职责边界。
3. 开发视图：项目、包、依赖、禁止跨层调用。
4. 进程视图：线程、任务、队列、并发、失败隔离。
5. 物理视图：部署节点、运行依赖、设备、网络、端口。

产出：`架构4+1视图.md`

---

## 6. 第五步：生成 RTM 和测试计划

使用模板：

- `../templates/需求追踪矩阵模板.md`
- `../templates/测试计划模板.md`

操作：

1. 把 PRD 中每条需求映射到设计、实现、测试。
2. 检查孤儿需求和幽灵实现。
3. 为核心规则设计正常、边界、异常测试。
4. 把时序图中的异常分支转成测试场景。

产出：

- `需求追踪矩阵.md`
- `测试计划.md`

---

## 7. 第六步：编码实现（阶段 E）

使用模板：

- `../templates/变更日志模板.md`

操作：

1. 按任务清单顺序逐个实现，不要一次性铺开。
2. 每个任务开始前，先读相关规格文档（数据字典/接口契约/通用约束/时序图）。
3. 先写测试（或至少同时写），再写实现。
4. 修改字段、规则、接口时，同步更新对应文档。
5. 每次关键修复记录变更日志（原因/影响面/关联需求编号）。

产出：代码 + 单元测试 + 变更日志

门禁：

- [ ] 核心逻辑有单元测试，且全部通过。
- [ ] 修改字段/规则/接口时文档已同步。
- [ ] 每次关键改动有变更日志记录。

---

## 8. 第七步：集成测试与回归验证（阶段 F）

使用模板：

- `../templates/测试计划模板.md`
- `../templates/需求追踪矩阵模板.md`

操作：

1. 按 RTM 逐项验证需求（不只挑“好测的”测）。
2. 按通用约束验证 P0/P1 规则。
3. 按时序图验证主链路和异常链路。
4. 对失败项分类根因（需求不清/数据不清/约束缺失/接口不清/流程不清/测试缺失）。

产出：测试报告 + 缺陷清单

门禁：

- [ ] RTM 逐项验证通过。
- [ ] 无 P0/P1 缺陷。
- [ ] 异常路径和边界条件已验证。

---

## 9. 第八步：发布准备与复盘（阶段 G）

使用模板：

- `../templates/硬件与部署清单模板.md`（涉及部署/硬件时）
- `../templates/变更日志模板.md`

操作：

1. 检查部署依赖，准备回滚方案。
2. 发布前确认测试报告、缺陷清单、回滚方案齐全。
3. 复盘时按根因分类问题，把经验沉淀回 InspireSpec。
4. 区分“项目特定修复”和“可复用方法论改进”。

产出：发布清单 + 复盘报告

门禁：

- [ ] 部署验证通过。
- [ ] 回滚方案已准备。
- [ ] 复盘报告已输出，经验已分类。

## 11. 快速验收

如果这些问题都能回答，说明规格基本可进入开发：

- 每个功能是否有验收标准？
- 每个核心字段是否有唯一语义？
- 每条 P0/P1 规则是否有测试点？
- 每个模块/API/设备接口是否有契约？
- 主流程和异常流程是否有 Mermaid 图？
- 每条需求是否能追踪到实现和测试？
