# 05-快速上手指南

> 本指南给出最短实操路径：从已有功能设计和界面设计，生成一套能指导开发的工程规格。

---

## 1. 开始前准备

你需要准备：

- 功能设计或项目设计文档。
- 页面流转图或业务流程说明。
- UI 设计稿、组件状态、交互说明。
- 技术栈或目标运行环境。
- 如果已有代码，也提供代码目录。
- 如果涉及硬件，提供设备型号、协议、部署环境。

---

## 2. 第一步：生成 PRD

使用模板：`../templates/PRD产品需求模板.md`

操作：

1. 从功能设计和界面稿提取用户角色。
2. 列出范围内和范围外。
3. 把每个功能写成可验收需求。
4. 补充性能、安全、兼容、稳定性要求。
5. 标出需要人工裁定的问题。

产出：`PRD产品需求文档.md`

---

## 3. 第二步：生成数据字典和通用约束

使用模板：

- `../templates/数据字典模板.md`
- `../templates/通用约束与业务规则模板.md`

操作：

1. 提取所有实体、字段、枚举和状态。
2. 绘制 Mermaid `erDiagram`。
3. 找出字段语义容易误解的地方。
4. 把跨模块规则集中成通用约束。
5. 为 P0/P1 规则写测试点。

产出：

- `数据字典与实体关系.md`
- `通用约束与业务规则.md`

---

## 4. 第三步：生成接口契约和核心时序图

使用模板：

- `../templates/接口契约模板.md`
- `../templates/核心流程时序图模板.md`

操作：

1. 列出核心模块、API、设备或外部系统。
2. 为每个接口写输入、输出、副作用、异常。
3. 为主链路画 Mermaid `sequenceDiagram`。
4. 为复杂状态画 `stateDiagram-v2`。
5. 检查接口两端是否匹配。

产出：

- `接口契约.md`
- `核心流程时序图.md`

---

## 5. 第四步：生成 4+1 架构视图

使用模板：`../templates/架构4+1视图模板.md`

操作：

1. 用例视图：用户、外部系统、设备和业务场景。
2. 逻辑视图：模块、领域对象、职责边界。
3. 开发视图：项目、包、依赖、禁止跨层调用。
4. 进程视图：线程、任务、队列、并发、失败隔离。
5. 物理视图：部署节点、运行依赖、设备、网络、端口。

产出：`架构4+1视图.md`

---

## 6. 第五步：生成 RTM 和测试计划

使用模板：

- `../templates/需求追踪矩阵模板.md`
- `../templates/测试计划模板.md`

操作：

1. 把 PRD 中每条需求映射到设计、实现、测试。
2. 检查孤儿需求和幽灵实现。
3. 为核心规则设计正常、边界、异常测试。
4. 把时序图中的异常分支转成测试场景。

产出：

- `需求追踪矩阵.md`
- `测试计划.md`

---

## 7. 第六步：开发、验证、复盘

使用模板：

- `../templates/变更日志模板.md`
- `../templates/硬件与部署清单模板.md`（涉及部署/硬件时）

操作：

1. 开发前先读 PRD、数据字典、通用约束、接口契约、时序图。
2. 修改字段、规则、接口时同步更新文档。
3. 每次关键修复记录原因和影响面。
4. 发布前检查测试、部署、回滚方案。
5. 复盘时把经验沉淀回 InspireSpec。

---

## 9. 快速验收

如果这些问题都能回答，说明规格基本可进入开发：

- 每个功能是否有验收标准？
- 每个核心字段是否有唯一语义？
- 每条 P0/P1 规则是否有测试点？
- 每个模块/API/设备接口是否有契约？
- 主流程和异常流程是否有 Mermaid 图？
- 每条需求是否能追踪到实现和测试？
