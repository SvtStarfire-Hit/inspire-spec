# 06-AI协作提示词

> 本文档提供可复制的提示词。原则：AI 负责提取、结构化、生成草案；人负责裁定和验收。

---

## 1. PRD 提示词

```text
请帮我生成 InspireSpec 阶段 A 的 PRD 产品需求文档。

项目信息：
- 项目名称：[名称]
- 功能设计材料：[路径/内容]
- 界面设计材料：[路径/内容]
- 技术/硬件背景：[说明]

请完成：
1. 提取用户角色和业务场景。
2. 明确范围内和范围外。
3. 将功能整理为 PRD-Fxx 需求条目。
4. 为每条需求写可验证的验收标准。
5. 补充性能、稳定性、安全、兼容性、可维护性需求。
6. 标出需要人工裁定的问题，不要自行决定。

输出格式参考 ../templates/PRD产品需求模板.md。
```

## 2. 数据字典与通用约束提示词

```text
请帮我执行 InspireSpec 阶段 B：数据建模与通用约束。

输入：
- PRD：[路径]
- 设计文档：[路径]
- 现有代码/数据库/接口：[路径]

请完成：
1. 提取所有核心实体、字段、枚举、状态。
2. 为每个字段定义类型、约束、默认值、语义。
3. 绘制 Mermaid erDiagram。
4. 找出语义模糊或多模块共用的字段。
5. 提取通用约束，包含编号、等级、影响模块、禁止事项、异常策略、测试点。
6. 对比现有代码或数据库，列出偏差。

输出：数据字典 + 通用约束两个文档。
```

## 3. 接口契约与时序图提示词

```text
请帮我执行 InspireSpec 阶段 C：接口契约、状态机与核心时序图。

输入：
- PRD：[路径]
- 数据字典：[路径]
- 通用约束：[路径]
- 核心模块/API/设备列表：[列表]

请完成：
1. 为每个核心接口写输入、输出、副作用、异常、权限、幂等性。
2. 特别标注容易误解的关键约定。
3. 为主业务链路生成 Mermaid sequenceDiagram。
4. 为异常链路补充 alt/else 分支。
5. 为复杂状态对象生成 stateDiagram-v2。
6. 检查接口调用两端是否匹配。

输出：接口契约 + 核心流程时序图。
```

## 4. 4+1 架构视图提示词

```text
请帮我执行 InspireSpec 阶段 D：4+1 架构视图。

输入：
- PRD：[路径]
- 数据字典：[路径]
- 通用约束：[路径]
- 接口契约：[路径]
- 技术栈/部署/硬件条件：[说明]

请完成：
1. 用例视图：用户、外部系统、设备、核心场景。
2. 逻辑视图：模块、领域对象、职责边界。
3. 开发视图：项目、包、依赖、禁止跨层调用。
4. 进程视图：线程、进程、队列、异步任务、失败隔离。
5. 物理视图：终端、服务器、设备、网络、端口、模型、配置。
6. 使用 Mermaid flowchart/classDiagram 表达关键结构。
7. 输出视图一致性检查。
```

## 5. RTM 与测试计划提示词

```text
请帮我执行 InspireSpec 阶段 D-F：需求追踪矩阵与测试计划。

输入：
- PRD：[路径]
- 数据字典：[路径]
- 通用约束：[路径]
- 接口契约：[路径]
- 时序图：[路径]

请完成：
1. 提取所有需求编号。
2. 建立需求→设计→接口/模块→代码→测试的映射。
3. 标出孤儿需求和幽灵实现。
4. 为每条 P0/P1 需求生成测试用例。
5. 将时序图中的异常路径转为测试场景。
6. 输出测试计划与回归清单。
```

## 6. 复盘与方法论回填提示词

```text
请帮我执行 InspireSpec 阶段 G：复盘与方法论回填。

输入：
- 本次变更日志：[路径]
- 缺陷清单：[路径]
- 测试报告：[路径]
- 相关规格文档：[路径]

请完成：
1. 总结哪些问题来自需求不清、数据不清、约束缺失、接口不清、流程不清或测试缺失。
2. 判断哪些经验应该回填到模板或方法论。
3. 输出“项目特定修复”和“可复用方法论改进”两类建议。
4. 不要把项目专有规则误写成通用规则。
```

---

## 7. 使用注意

- 不要让 AI 自行裁定业务冲突。
- 不要跳过通用约束直接写接口。
- 不要只画正常流程，必须包含异常路径。
- 不要让 Mermaid 图与接口契约使用不同模块名。
- 不要把项目案例中的特定规则当成所有项目的通用规则。
